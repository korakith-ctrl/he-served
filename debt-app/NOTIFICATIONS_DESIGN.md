# เคลียร์กัน — แบบ Push Notification สำหรับ PWA

สถานะ: เอกสารข้อเสนอเดิม มีการพัฒนาแล้วใน workspace; รายละเอียดที่ส่งมอบจริงและขั้นตอนเปิดใช้งานอยู่ใน [PUSH_SETUP.md](./PUSH_SETUP.md) ยังไม่ได้ deploy หรือทดสอบ Push บนอุปกรณ์จริง

## แนวทาง

แจ้งเมื่อมีสิ่งที่ควรรู้หรือทำต่อ ใช้ข้อความสุภาพ ไม่เร่งรัดหรือกล่าวโทษ กดแล้วเข้ารายการที่เกี่ยวข้องทันที หน้าตาภายในแอปใช้สีเขียวเข้ม พื้นครีม และสี coral ของแอปเดิม ส่วนการแจ้งเตือนบนหน้าจอล็อกใช้รูปแบบที่ระบบปฏิบัติการกำหนด

ค่าเริ่มต้นซ่อนชื่อบุคคล ชื่อรายการ ยอดเงิน และรายละเอียดข้อโต้แย้งบนหน้าจอล็อก ผู้ใช้เปิดแสดงรายละเอียดได้ในตั้งค่า การแจ้งเตือนในแอปหลังเข้าสู่ระบบแสดงรายละเอียดตามสิทธิ์เดิม

## หน้าจอและการขอสิทธิ์

แสดงการ์ดเชิญเปิดแจ้งเตือนในหน้ากระดิ่งหลังผู้ใช้มีรายการแรก ไม่เด้งขอสิทธิ์ทันทีเมื่อเข้าเว็บ

```text
┌──────────────────────────────────────┐
│ 🔔 ไม่พลาดเรื่องที่ต้องเคลียร์         │
│ เตือนวันชำระและอัปเดตจากคู่สัญญา      │
│ แม้ไม่ได้เปิดแอป                      │
│                                      │
│ ซ่อนชื่อและยอดเงินบนหน้าจอล็อก        │
│ [ เปิดการแจ้งเตือน ]     ไว้ทีหลัง     │
└──────────────────────────────────────┘

การแจ้งเตือน                     ตั้งค่า
[ทั้งหมด] [ต้องดำเนินการ] [ยังไม่อ่าน]

วันนี้
● มีรายการชำระให้ตรวจสอบ            ›
  เปิดดูรายละเอียดและตรวจสอบหลักฐาน
  10 นาทีที่แล้ว

  ยืนยันการชำระแล้ว                  ›
  ดูสถานะล่าสุดของรายการได้ในแอป
  1 ชั่วโมงที่แล้ว
```

- กด “เปิดการแจ้งเตือน” จึงเรียกหน้าต่างขอสิทธิ์ของเบราว์เซอร์จากการกดของผู้ใช้โดยตรง
- iPhone/iPad ที่ยังไม่ได้ติดตั้ง: แสดง “เพิ่มเคลียร์กันไปยังหน้าจอโฮม” พร้อมขั้นตอนเมนูแชร์ → เพิ่มไปยังหน้าจอโฮม → เปิดแอปจากไอคอน → กลับมากดเปิดแจ้งเตือน ตรวจความสามารถจริงประกอบการตรวจโหมด standalone
- เลือก “ไว้ทีหลัง”: ซ่อนการ์ด 7 วัน แต่เปิดจากตั้งค่าได้ตลอด
- ถูกปฏิเสธสิทธิ์: แสดง “การแจ้งเตือนถูกปิดในอุปกรณ์นี้” และวิธีแก้จากการตั้งค่าเบราว์เซอร์/ระบบ ไม่เรียกขอซ้ำอัตโนมัติ
- ไม่รองรับ: แสดง “อุปกรณ์นี้ใช้การแจ้งเตือนในแอปได้” พร้อมรายการในกระดิ่งตามเดิม
- อนุญาตแล้วแต่ลงทะเบียนไม่สำเร็จ: แสดง “เชื่อมต่อการแจ้งเตือนไม่สำเร็จ” และปุ่มลองใหม่ ห้ามแสดงว่าเปิดใช้งานสำเร็จจาก permission เพียงอย่างเดียว
- ลงทะเบียนสำเร็จ: แสดง “เปิดการแจ้งเตือนบนอุปกรณ์นี้แล้ว” พร้อมปุ่ม “ส่งทดสอบ” ที่ผู้ใช้กดเอง

ตั้งค่าแสดงสถานะอุปกรณ์นี้, เปิด/ปิด Push บนอุปกรณ์นี้, หมวดวันชำระ, หมวดคำขอและการชำระ, เวลาเตือน (เริ่มต้น 09:00 Asia/Bangkok), ช่วงพัก (21:00–08:00), พัก 7 วัน, การแสดงข้อมูลบนหน้าจอล็อก และอุปกรณ์ที่รับแจ้งเตือน การปิด Push ไม่ปิดกล่องแจ้งเตือนในแอป

ปุ่มสัมผัสอย่างน้อย 44px, สถานะไม่อาศัยสีอย่างเดียว, รองรับ keyboard/focus, คืน focus ไปปุ่มกระดิ่งเมื่อปิด dialog และเคารพ reduced motion

## เหตุการณ์และข้อความเริ่มต้น

ทุกหมวดเปิดหลังผู้ใช้เลือกเปิด Push สำเร็จเท่านั้น ผู้ใช้ปิดแยกหมวดได้

| เหตุการณ์ | ผู้รับ / เวลา | หัวข้อ — ข้อความบนหน้าจอล็อก | กดแล้วไป |
| --- | --- | --- | --- |
| ก่อนครบกำหนด 3 วัน | ผู้จ่าย / เวลาเตือน | ใกล้ถึงวันชำระแล้ว — มีรายการที่จะครบกำหนดในอีก 3 วัน ดูรายละเอียดในเคลียร์กัน | งวดที่เกี่ยวข้อง |
| ครบกำหนดวันนี้ | ผู้จ่าย / เวลาเตือน | วันนี้มีรายการครบกำหนด — เปิดดูรายการและอัปเดตการชำระได้ในแอป | งวดที่เกี่ยวข้อง |
| หลังครบกำหนด 1 วัน | ผู้จ่าย / ครั้งเดียว | ตรวจสอบสถานะการชำระ — มีรายการที่เลยวันครบกำหนดแล้ว หากชำระแล้วอัปเดตได้ในแอป | งวดที่เกี่ยวข้อง |
| แจ้งชำระใหม่ | ผู้รับเงิน / หลังบันทึกสำเร็จ | มีรายการชำระให้ตรวจสอบ — เปิดดูรายละเอียดและตรวจสอบหลักฐาน | รายการชำระ |
| ยืนยันรับเงิน | ผู้จ่าย / หลังยืนยันสำเร็จ | ยืนยันการชำระแล้ว — ดูสถานะล่าสุดของรายการได้ในแอป | ประวัติชำระ |
| ไม่รับรายการชำระ | ผู้จ่าย / หลังบันทึกสำเร็จ | รายการชำระต้องตรวจสอบอีกครั้ง — เปิดดูรายละเอียดจากคู่สัญญาในแอป | รายการชำระ |
| คำเชิญ / ขอแก้ไข / ขอความยินยอม / แผนชำระ | ผู้ที่ต้องตอบ / หลังบันทึกสำเร็จ | มีคำขอให้คุณตรวจสอบ — อ่านรายละเอียดก่อนยืนยันในเคลียร์กัน | คำขอ |
| ผลคำขอ / ยกเลิก / ย้อนชำระ / ข้อโต้แย้ง | อีกฝ่ายที่เกี่ยวข้อง / หลังบันทึกสำเร็จ | มีอัปเดตในรายการของคุณ — เปิดดูสถานะล่าสุดในเคลียร์กัน | ประวัติรายการ |

ไม่แสดงปุ่มยืนยันรับเงินหรือยอมรับข้อตกลงบน Push ต้องเปิดแอปและตรวจรายละเอียดก่อนเสมอ คำเชิญแบบลิงก์ที่ยังไม่ทราบบัญชีผู้รับไม่ส่ง Push

## กติกาลดการรบกวน

- เตือนตามยอดคงเหลือของแต่ละงวดและวันครบกำหนดล่าสุด ตัดรายการปิดแล้ว ยกเลิก เก็บถาวร หรือไม่มีกำหนดชำระออก
- หากมียอดแจ้งชำระรอตรวจครบยอดงวด ให้พักการเตือนงวดนั้น หากรอตรวจเพียงบางส่วน เตือนเฉพาะยอดที่ยังไม่ได้แจ้งชำระ โดยคำนวณฝั่งเซิร์ฟเวอร์
- รวมรายการครบกำหนดหลายรายการเป็น Push สรุปเดียวต่อผู้ใช้ต่อวัน เช่น “วันนี้มี 3 รายการให้ตรวจสอบ” กล่องในแอปยังมีรายละเอียดแยกรายการ
- การเตือนตามเวลาสูงสุด 1 Push ต่อวันต่อบัญชี; เหตุการณ์จากคู่สัญญาส่งตามเหตุการณ์ แต่รวม burst ภายใน 60 วินาทีเป็นข้อความกลางและลิงก์เข้ากล่องแจ้งเตือน
- ช่วงพักใช้กับทุกหมวด เก็บเหตุการณ์ในแอปทันทีและส่งสรุปที่ยังเกี่ยวข้องเมื่อหมดช่วงพัก ไม่ส่งย้อนหลังทีละข้อความ
- พัก 7 วันหยุด Push ทุกหมวดจนถึงเวลาที่แสดงในตั้งค่า
- ก่อนส่งตรวจสถานะล่าสุด สิทธิ์ผู้รับ การตั้งค่า และ readAt อีกครั้ง ตัดเหตุการณ์ที่อ่านแล้วหรือหมดความเกี่ยวข้อง
- Push เตือนหมดอายุหลัง 2 ชั่วโมง ส่วนเหตุการณ์คู่สัญญาหลัง 24 ชั่วโมง; ข้อความที่ส่งเข้าระบบ Push ไปแล้วอาจเรียกคืนไม่ได้ จึงเปิดดูสถานะสดเสมอ
- ไม่รับประกันเวลาส่งถึง และไม่ใช้การส่ง Push เป็นหลักฐานว่าอีกฝ่ายรับทราบหรือยอมรับข้อตกลง

## โครงสร้างที่ต่อกับโค้ดเดิม

ปัจจุบัน `functions/index.js` สร้าง `debtNotifications/{uid}/{notificationId}` ผ่าน `addDebtNotification` และหน้า `NotificationsPanel` ใน `debt-app/src/App.jsx` อ่านข้อมูลนี้อยู่แล้ว ให้ใช้กล่องเดิมเป็นแหล่งข้อมูลหลัก

`refreshDebtReminders` ปัจจุบันเป็น callable ที่เรียกจากแอป ตรวจ `debt.dueDate` และใช้ key เดียวต่อหนี้/วันครบกำหนด จึงยังไม่รองรับการเตือนหลายช่วงและทุกงวดอย่างครบถ้วน ต้องแยก logic การหาเหตุการณ์มาใช้ร่วมกับ scheduled function; ห้ามเพิ่ม scheduler ที่ส่งซ้ำกับ callable เดิม

```text
การเปลี่ยนสถานะ / งานตรวจวันครบกำหนดทุก 15 นาที
  → บันทึกกล่องแจ้งเตือนด้วย event key ที่ไม่ซ้ำ
  → Realtime Database on-create trigger
  → outbox / งานรอส่งตามช่วงพักและการรวมข้อความ
  → ตรวจสิทธิ์ + สถานะ + preferences อีกครั้ง
  → Firebase Admin Messaging → FCM → Service Worker
  → แจ้งเตือนระบบ → เข้าสู่ระบบ → เปิดรายการ
```

เลือก FCM เพราะโครงการใช้ Firebase อยู่แล้ว เพิ่ม Firebase Messaging ที่ client และ Service Worker เฉพาะ origin ของ debt-app ใช้ `isSupported()` และ HTTPS ตรวจความพร้อม ไม่ปะปน registration กับแอปร้านกาแฟ

ข้อมูลเสนอเพิ่ม:

| Path | หน้าที่ / สิทธิ์ |
| --- | --- |
| `debtPushPreferences/{uid}` | หมวด, timezone, reminderTime, quietHours, pausedUntil, showSensitivePreview; เจ้าของอ่านและแก้ผ่าน callable ที่ตรวจข้อมูล |
| `debtPushDevices/{uid}/{installationId}` | FCM token, enabled, updatedAt, lastSeenAt; server-only, UI อ่าน metadata ที่ไม่มี token ผ่าน callable |
| `debtPushOutbox/{deliveryKey}` | pending/leased/sent/failed, attempts, nextAttemptAt, expiresAt; server-only |
| `debtReminderIndex/{date}/{eventKey}` | ดัชนีงวดที่ต้องตรวจ รวมการแก้ไขหรือยกเลิกกำหนด; server-only |

เพิ่ม API `registerDebtPushDevice`, `disableDebtPushDevice`, `getDebtPushDevices`, `updateDebtPushPreferences`, `sendDebtPushTest` โดยใช้ Auth, App Check, validation และ rate limit ตามรูปแบบเดิม ไม่รับ uid ผู้รับจาก client โดยไม่มีการตรวจเจ้าของ

event key เตือนใช้ uid + debtId + installmentId + dueDate + stage เพื่อแยกก่อนกำหนด/วันจริง/หลังกำหนด; delivery key เพิ่ม installationId ใช้ transaction ยึดงานพร้อม lease และ retry แบบ backoff ลบ token ที่ FCM ระบุว่าใช้ไม่ได้ หยุดเมื่อพ้น expiresAt การส่งแบบ at-least-once ยังมีโอกาสซ้ำเมื่อ process หยุดหลังส่งสำเร็จ ใช้ notification tag คงที่ช่วยลดการแสดงซ้ำ ไม่อ้าง exactly-once

ออกจากระบบหรือเปลี่ยนบัญชีต้องเลิกผูก installation กับบัญชีเก่าก่อนผูกใหม่ ลบ token ฝั่ง client และเคลียร์ notification ที่แสดงอยู่เท่าที่ API รองรับ หาก offline ให้บันทึกงานยกเลิกเพื่อลองใหม่และอย่าแสดงข้อมูลละเอียดใน payload ค่าเริ่มต้น เพราะ server อาจยังไม่ทราบการออกจากระบบ

ส่ง notification payload ให้ระบบแสดงเบื้องหลังผ่าน FCM เพียงเส้นทางเดียว ไม่เรียก showNotification ซ้ำใน background handler; foreground ใช้ onMessage อัปเดตกล่อง/แสดง toast สั้น ๆ ด้วย notificationId เดิม ต้องทดสอบพฤติกรรมจริงรายเบราว์เซอร์

deep link เสนอ `/?notification=<id>` เก็บปลายทางผ่านขั้นตอน login แล้วโหลด notification ของ uid ปัจจุบันเพื่อหา debt/payment/request ไม่เชื่อ URL ภายนอกจาก payload และตรวจ membership ฝั่งฐานข้อมูล/เซิร์ฟเวอร์ทุกครั้ง หากไม่มีสิทธิ์แล้วแสดง “รายการนี้ไม่พร้อมให้เปิดดู” หาก offline แสดงให้เชื่อมต่อก่อนโหลดข้อมูล ไม่ทำเครื่องหมายอ่านแค่เพราะได้รับ Push

## ขอบเขตการส่งมอบและเกณฑ์ตรวจรับ

1. เพิ่มหน้าตั้งค่า/สถานะขอสิทธิ์และ Service Worker พร้อมการลงทะเบียน/ยกเลิกอุปกรณ์
2. เชื่อมเหตุการณ์คู่สัญญาเดิมกับ outbox และ FCM พร้อม deep link
3. ย้าย logic เตือนวันครบกำหนดไปใช้ร่วมกับ scheduler และรองรับงวด/การเปลี่ยนแผนชำระ
4. เพิ่มการรวมข้อความ ช่วงพัก การหมดอายุ และตัวนับความสำเร็จ/ข้อผิดพลาดที่ไม่บันทึก token หรือรายละเอียดหนี้ลง log

ตรวจบน Android Chrome, iPhone/iPad ที่ติดตั้งบน Home Screen และ desktop ที่รองรับ: foreground/background/ปิดหน้าต่างแอป, permission default/denied/granted, registration ล้มเหลว, offline, token หมดอายุ, หลายอุปกรณ์, logout/สลับบัญชี, กด Push หลังสิทธิ์ถูกยกเลิก และการส่งทดสอบมี rate limit

ทดสอบกติกาด้วยเวลา Asia/Bangkok ข้ามเที่ยงคืน/ช่วงพัก, วันครบกำหนดที่แก้แล้ว, งวดที่ชำระบางส่วน/รอตรวจ/ครบยอด, รายการไม่มีกำหนด, trigger ซ้ำ, retry หลัง worker หยุด และเหตุการณ์ที่อ่านก่อนส่ง โดยยืนยันว่าไม่แก้ไขสถานะการเงินจากการรับหรือกด Push

- [WebKit: Web Push for Web Apps on iOS and iPadOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/) — iOS/iPadOS 16.4 ขึ้นไปรองรับ Push สำหรับเว็บแอปบน Home Screen และการขอสิทธิ์ต้องมาจากการกระทำของผู้ใช้

แบบนี้ยังไม่ได้ทดสอบการส่งบนอุปกรณ์จริง การพัฒนาต้องตั้งค่า Web Push credentials ของ Firebase, deploy Functions/Rules/Service Worker และตรวจรับก่อนเปิดใช้งาน
