# แบบฟีเจอร์: บันทึกรายรับ–รายจ่ายประจำวัน

สถานะ: **พัฒนาในเครื่องแล้ว ยังไม่ได้ deploy**

## ภาพรวม

เพิ่มสมุดรายการเงินจริงในพื้นที่ **การเงินของฉัน → รายรับ–รายจ่าย** เพื่อให้ผู้ใช้บันทึกเงินเข้าและเงินออกตามวันที่เกิดขึ้นจริง ดูยอดสุทธิรายวันและรายรอบเงินเดือน และเทียบกับแผนรายรับรายจ่ายที่มีอยู่แล้วได้

ข้อมูลเดิมใน `incomes` และ `expenses` เป็น **แผน** (ทุกเดือนหรือครั้งเดียว) ปัจจุบันระบบนำแผนนี้ไปคำนวณรอบเงินเดือน แม้ยังไม่ได้รับหรือจ่ายเงินจริง ส่วน `payments` เป็นเงินชำระหนี้ส่วนตัวที่เกิดขึ้นแล้ว และ `debtPayments` เป็นเงินระหว่างบุคคลที่ต้องรออีกฝ่ายยืนยัน การแยกสถานะเหล่านี้ให้ชัดคือหัวใจของฟีเจอร์

## หน้าจอและเส้นทางใช้งาน

ในแท็บ **รายรับ–รายจ่าย** เสนอให้เรียงส่วนย่อยเป็น **บันทึกประจำวัน · แผนประจำ · เชื่อมกับคนอื่น · ปฏิทิน** โดยย้ายหน้าจอ “ส่วนตัว” เดิมไปอยู่ใต้ชื่อ “แผนประจำ” และเปิด “บันทึกประจำวัน” เป็นค่าเริ่มต้น ปฏิทินมีตัวเลือก **รายการจริง / แผน** ชัดเจน

```text
การเงินของฉัน  >  รายรับ–รายจ่าย
┌─────────────────────────────────────────────┐
│ รอบเงินเดือน 25 ก.ย. – 24 ต.ค.               │
│ [บันทึกประจำวัน] [แผนประจำ] [เชื่อมกับคนอื่น] [ปฏิทิน] │
├─────────────────────────────────────────────┤
│ วันนี้ 24 ก.ย.              [+ บันทึกรายการ]  │
│ รับจริง +2,000  จ่ายจริง −450  สุทธิ +1,550  │
│                                             │
│ พฤ. 24 ก.ย.          รับ +2,000  จ่าย −450  │
│  ค่าอาหาร · อาหาร · เงินสด            −150  │
│  ค่าน้ำมัน · เดินทาง · โอน             −300  │
│  งานเสริม · รายได้เสริม              +2,000  │
│                                             │
│ พ. 23 ก.ย.                                  │
│  ชำระบัตรเครดิต · จากข้อมูลหนี้       −1,500  │
│  รับชำระจากคุณ ก · ยืนยันแล้ว          +800  │
└─────────────────────────────────────────────┘
```

**บันทึกด่วน:** กด “+ บันทึกรายการ” → เลือก “รายรับ” หรือ “รายจ่าย” → กรอกจำนวนเงิน ชื่อรายการ วันที่ (วันนี้เป็นค่าเริ่มต้น) และหมวด → บันทึก ช่องทางเงินสด/โอนและหมายเหตุเป็นข้อมูลเสริม วันที่จริงเลือกย้อนหลังได้ แต่ไม่เลือกอนาคต ระหว่างกรอก สามารถเลือก “อ้างอิงแผน” จากรายการประจำหรือตามวันที่กำหนดได้ เมื่อเลือกแผน ให้เติมชื่อ หมวด และยอดเป็นค่าเริ่มต้น แต่ผู้ใช้แก้ยอดจริงได้ และเลือก “ครบแล้ว” หรือ “ยังมีส่วนที่เหลือ” เพื่อบอกว่ารอบของแผนนั้นจบหรือยัง

**รายการที่เชื่อม:** แตะรายการชำระหนี้ส่วนตัวเพื่อเปิดประวัติการชำระ แตะรายการระหว่างบุคคลเพื่อเปิดข้อตกลงต้นทาง รายการเหล่านี้แสดงป้าย “เชื่อมจากหนี้” และแก้ไขจากหน้าต้นทางเท่านั้น ในเมนูบันทึกด่วน ถ้าเลือก “ชำระหนี้ของฉัน” ให้พาไปฟอร์มชำระหนี้เดิม; ถ้าเลือก “จ่าย/รับกับคนอื่น” ให้พาไปข้อตกลงที่เกี่ยวข้อง

**ภาพรวม:** เพิ่มแถว “เกิดขึ้นจริงในรอบนี้” ที่แสดงรายรับจริง รายจ่ายทั่วไปจริง ชำระหนี้จริง และสุทธิจริง โดยคงการ์ดแผนที่มีอยู่ และติดป้าย “คาดการณ์” ให้ยอดเงินคงเหลือกับงบใช้ได้ต่อวัน ผู้ใช้จึงไม่เข้าใจว่ายอดคาดการณ์เป็นเงินในบัญชีจริง

## การเชื่อมข้อมูล

| แหล่งข้อมูล | แสดงในบันทึกประจำวัน | ผลต่อแผน/หนี้ |
| --- | --- | --- |
| `personalFinance/{uid}/dailyTransactions` ใหม่ | รายรับ/รายจ่ายที่ผู้ใช้บันทึกเอง | ถ้าผูกแผน ให้หักยอดที่เกิดจริงจากยอดแผนที่ยังคาดว่าจะเกิดในรอบนั้น |
| `personalFinance/{uid}/incomes`, `expenses` เดิม | ไม่แสดงเป็นเงินจริงจนกว่าจะบันทึก | ใช้สร้างรายการคาดการณ์ตามรอบเงินเดือนเหมือนเดิม |
| `personalFinance/{uid}/payments` เดิม | แสดงเป็น “ชำระหนี้ของฉัน” ตามวันที่จ่าย | ยอดหนี้และรอบบิลยังอัปเดตผ่านฟอร์มชำระเดิม |
| `debtPayments/{debtId}` | แสดงเมื่อ `status === confirmed` ตาม `paymentDate`; `pending` แสดงแยกเป็นรอยืนยัน | ใช้ `debtId/paymentId` เป็นรหัสอ้างอิง เปิดรายการต้นทางได้; `reversed` ไม่รวมยอดจริง |
| `liabilities`, `cardStatements`, ข้อตกลงระหว่างบุคคล | ไม่สร้างรายการรายวันจากยอดค้างหรือวันครบกำหนด | ยังคงเป็นภาระ/กำหนดจ่ายในแผน; การชำระจริงมาจาก payment เท่านั้น |

**กติกาไม่ให้นับซ้ำ:** รายการประจำเป็นแผน ไม่ใช่ธุรกรรมจริง รายการชำระหนี้ที่มีต้นทางอยู่แล้วไม่สร้าง `dailyTransactions` ซ้ำหนึ่งชุด ถ้าบันทึกค่าใช้จ่ายประจำ 3,000 บาท แล้วจ่ายจริง 2,800 บาทและเลือก “ยังมีส่วนที่เหลือ” แผนส่วนนั้นจะเหลือคาดการณ์ 200 บาทในรอบเดียวกัน; ถ้าเลือก “ครบแล้ว” ส่วนที่เหลือเป็น 0 และแสดงว่าจ่ายต่ำกว่าแผน 200 บาท การบันทึกหลายครั้งอ้างแผนเดียวกันรวมยอดก่อนเทียบกับแผน

**เวลาของรายการ:** ใช้วันที่ `YYYY-MM-DD` ในเวลาไทยสำหรับการจัดกลุ่มและรอบเงินเดือน ส่วน `createdAt`/`updatedAt` เป็น ISO timestamp สำหรับตรวจลำดับการแก้ไข รายการยืนยันระหว่างบุคคลใช้ `paymentDate` เป็นวันที่เงินเคลื่อนจริง และแสดงวันที่ยืนยันเป็นข้อมูลประกอบหากต่างกัน

## โครงข้อมูลที่เสนอ

```json
"personalFinance": {
  "{uid}": {
    "dailyTransactions": {
      "{transactionId}": {
        "direction": "expense",
        "amount": 150.00,
        "date": "2026-09-24",
        "title": "ค่าอาหาร",
        "category": "อาหาร",
        "method": "cash",
        "note": "",
        "planRef": { "kind": "expense", "id": "{expenseId}", "occurrenceDate": "2026-09-24", "completesOccurrence": true },
        "createdAt": "2026-09-24T07:00:00.000Z",
        "updatedAt": "2026-09-24T07:00:00.000Z"
      }
    }
  }
}
```

`planRef` ไม่บังคับ และใช้ `occurrenceDate` เพื่อให้รายการประจำเดือนหลายรอบไม่หักกันข้ามรอบ หมวดและชื่อเก็บ snapshot ในธุรกรรมจริง เพื่อให้ประวัติไม่เปลี่ยนเมื่อแก้ชื่อแผนในภายหลัง จำนวนเงินเก็บเป็นบาททศนิยมสองตำแหน่งใน UI; ฝั่งคำนวณควรแปลงเป็นสตางค์เพื่อเลี่ยงความคลาดเคลื่อน

## กติกายอดสรุป

- **เงินจริงสุทธิของช่วงที่เลือก** = รายรับจริงทั้งหมด − รายจ่ายทั่วไปจริง − ชำระหนี้จริง โดยรายรับจากคนอื่นนับเมื่อยืนยันแล้ว
- **คาดการณ์เมื่อจบรอบ** = เงินจริงที่เกิดในรอบ + รายรับตามแผนที่ยังไม่เกิด − รายจ่ายตามแผนที่ยังไม่เกิด − ภาระหนี้ที่ยังต้องชำระในรอบ
- **ยอดแผนที่ยังไม่เกิดของแต่ละรายการ** = `max(0, ยอดแผน − ยอดจริงที่ผูกกับแผนใน occurrence เดียวกัน)` ถ้าผู้ใช้ระบุว่า “ครบแล้ว” ให้เป็น 0 แม้จ่ายหรือรับจริงต่ำกว่าแผน รายการจริงที่ไม่ได้ผูกแผนถือเป็นรายการเพิ่มจากแผน
- ภาระหนี้ต้องใช้ **ยอดยังไม่จ่าย** ในรอบ: บัตรเครดิตใช้ยอดใบแจ้งหนี้ลบ `paidAmount`; หนี้ส่วนตัวและหนี้ระหว่างบุคคลใช้ยอดคงเหลือหรือยอดงวดที่ยังไม่ชำระ จึงไม่บวกยอดชำระจริงซ้ำกับยอดเต็มก่อนจ่าย
- **DTI** ยังแสดงจากภาระหนี้ตามแผนต่อรายรับตามแผน เพราะเป็นตัวชี้วัดภาระ ไม่เปลี่ยนเป็น DTI จากรายการจ่ายรายวัน
- ตัวเลข “เงินจริงสุทธิ” เป็นกระแสเงินสดในช่วงที่เลือก **ไม่ใช่ยอดคงเหลือในบัญชีธนาคาร** เพราะแอปยังไม่มีเงินตั้งต้นและยอดแต่ละบัญชี

## พฤติกรรมและขอบเขตระยะแรก

- เพิ่ม แก้ไข และลบรายการที่บันทึกเองได้ พร้อมข้อความยืนยันก่อนลบ; รายการจากแหล่งอื่นเปิดแก้ที่ต้นทาง
- กรองตามวันที่ รายรับ/รายจ่าย หมวด และแหล่งข้อมูล; ค่าเริ่มต้นเป็นรอบเงินเดือนที่เลือกอยู่
- รายการที่รอยืนยันจากคนอื่นอาจเห็นในกลุ่ม “รอยืนยัน” แต่ไม่รวมยอดเงินจริง; ปฏิเสธหรือย้อนรายการแล้วต้องหายจากยอดจริงทันที
- การชำระหนี้ส่วนตัวที่ลบหรือย้อนจากหน้าหนี้ต้องอัปเดตบันทึกประจำวันทันที เพราะบันทึกประจำวันอ่านต้นทางเดียวกัน
- ใช้สิทธิ์ `personalFinance/{uid}` ที่มีอยู่สำหรับรายการที่บันทึกเอง; ข้อมูลการชำระระหว่างบุคคลอ่านตามสิทธิ์คู่สัญญาที่มีอยู่ ไม่คัดลอกสลิปหรือข้อมูลอีกฝ่ายลงพื้นที่ส่วนตัว
- ระยะแรกยังไม่ทำยอดบัญชีธนาคาร การเชื่อมธนาคาร หรือการลงรายการซื้อด้วยบัตรเครดิตเป็นธุรกรรมเงินสด เพราะต้องมีบัญชี/ยอดเปิดต้นและกติกาเคลียร์ใบแจ้งหนี้เพิ่ม

## ตัวอย่างที่ควรใช้ตรวจรับ

1. เงินเดือนวางแผน 30,000 บาท วันที่ 25; บันทึกรับจริง 29,500 บาทโดยผูกแผนและเลือก “ครบแล้ว” → รับจริง 29,500 และไม่คาดว่าจะรับเพิ่มในรอบนั้น
2. ค่าเช่าวางแผน 8,000 บาท; บันทึกจ่ายจริง 5,000 บาทโดยเลือก “ยังมีส่วนที่เหลือ” → รายจ่ายจริง 5,000 และแผนคงค้าง 3,000; เมื่อบันทึกอีก 3,000 และเลือก “ครบแล้ว” แผนคงค้างเป็น 0
3. ชำระบัตร 1,500 บาทผ่านหน้าหนี้ → มีรายการจริงหนึ่งรายการในวันชำระ; ยอดใบแจ้งหนี้ที่ยังคาดว่าจะจ่ายลดลง 1,500
4. ลูกหนี้แจ้งจ่าย 800 บาทแต่เจ้าหนี้ยังไม่ยืนยัน → แสดงรอยืนยัน ไม่เพิ่มรายรับจริง; หลังยืนยันเพิ่ม 800; หากย้อนชำระให้เอาออกจากยอดจริง
5. บันทึกค่าอาหาร 150 บาทโดยไม่ผูกแผน → เพิ่มรายจ่ายจริง 150 และลดคาดการณ์ปลายรอบ 150

## ตัวเลือกที่ใช้ในรุ่นนี้

1. “บันทึกประจำวัน” เป็นหน้าแรกของแท็บรายรับ–รายจ่าย
2. ผู้ใช้เลือกผูกแผนเองจากรายการของรอบเงินเดือนที่เปิดอยู่
3. การซื้อด้วยบัตรเครดิตยังไม่เป็นรายการเงินจริง; การจ่ายใบแจ้งหนี้เข้าบันทึกจากประวัติชำระหนี้
